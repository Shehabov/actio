# BUGS.md

The defect register. Every bug found in Actio, and every mistake an agent has made
building it, is recorded here so it is not committed a second time.

`bug-historian` owns this file. It is the only agent that writes to it, and it reads it at
the start of every run to brief the swarm on what has already gone wrong on the surface
being touched.

**If you are an agent starting work: read the entries tagged with the surface or the
component you are about to change, before you plan.** A defect that repeats is worse than
a defect that is new, because it means the register was written and nobody read it.

---

## How to use this file

| You are | Do this |
|---|---|
| Shehab | Raise anything. One line is enough. `bug-historian` fills in the rest. |
| `qc-engineer` or `qc-lead` | File the defect here as well as in the run, with reproduction steps and the evidence path. |
| Any other agent | Do not edit this file. Report the defect to `bug-historian` in your handoff and it records it. |
| Any agent starting a run | Read it. Filter by `surface` and `agent`. Carry the relevant entries into your plan's audit step. |

---

## Entry format

Every entry is one block. Never delete an entry: close it, and keep it.

```markdown
### BUG-0007 · Below-threshold error named the filter that caused it

| | |
|---|---|
| Status | closed |
| Raised by | qc-engineer |
| Raised on | 2026-09-20 |
| Run | 2026-09-20-privacy-preview |
| Surface | api/reports |
| Component | `surveys/services/reporting.py` |
| Agent at fault | backend-engineer |
| Class | privacy-invariant |
| Severity | blocker |
| Evidence | `.actio/runs/2026-09-20-privacy-preview/evidence/inv-i2-filter.log` |
| Fixed in | `fix/below-threshold-leak`, closed 2026-09-20 |
| Repeat of | none |

**What happened.** The 409 body carried the field that dropped the cohort under five.

**Why it got through.** The invariant was tested on the data path and not on the error
path. The test asserted the request was refused, not what the refusal said.

**The rule this produces.** An error raised by a privacy invariant states the invariant,
never the input that tripped it. Applies to every invariant, not only this one.

**Who must be briefed.** backend-engineer, qc-engineer, code-analyst.

**How to detect it next time.** grep for `raise BelowThreshold` and confirm no call site
passes a field name, a filter key or a count into the exception.
```

### Fields that matter

| Field | Why |
|---|---|
| `Agent at fault` | Not blame. It is how the brief gets routed to the right agent next run. Where the fault is the brief or the spec rather than the implementer, say so. |
| `Class` | The taxonomy below. It is what makes the register searchable. |
| `Repeat of` | If this is the second time, name the earlier id. A repeat is a process failure and escalates to Shehab. |
| `The rule this produces` | The generalised lesson. A register of incidents teaches nothing; a register of rules teaches. |
| `How to detect it next time` | A concrete check, ideally a command. This is what makes the entry actionable rather than a story. |

## Classes

| Class | Means |
|---|---|
| `privacy-invariant` | I1 to I4. Threshold, filtering, free text, protected cases. The most serious class. |
| `state-machine` | I5 to I7. Closure without evidence, illegal transition, lane without authority. |
| `contract` | Front end and back end disagreed about the API shape. |
| `correctness` | A plain bug: logic, null, boundary, timezone, race. |
| `security` | Authorisation, injection, secrets, personal data in a log or a URL. |
| `data-layer` | N+1, missing index, unbounded query, migration lock, non-reversible migration. |
| `brand` | A token, contrast, type, spacing, motion or copy rule broken. |
| `design-system` | Shell, inversion rule, component anatomy, density, state coverage. |
| `locale` | Arabic, RTL, length, plurals, a string concatenated with a count. |
| `accessibility` | Contrast, focus, target size, colour as the sole carrier, screen reader. |
| `process` | A gate skipped, a handoff unread, an agent not utilised, a rejection loop. |
| `agent-behaviour` | An agent did something it is told not to do: invented a value, marked work done without evidence, narrowed scope silently, added attribution. |

## Standing rules

Rules produced by closed defects. **These are binding, and `bug-historian` briefs them at
the start of every run that touches the named surface.** A rule here outranks an agent's
instinct.

| # | Rule | From | Binds |
|---|---|---|---|
| R-01 | An error raised by a privacy invariant states the invariant, never the input that tripped it. | BUG-0007 | backend-engineer, code-analyst, qc-engineer |
| R-02 | A citation of a `BRAND.md` section is checked against the file before it is written. Section numbers are not remembered, they are read. | BUG-0002 | every agent |
| R-03 | Where two files define the same schema, one is the source and the other references it. Never two copies. | BUG-0003 | tech-architect, orchestrator |
| R-04 | A value that is not on the spacing scale or the type scale is not written, even when it looks right. If the value you want is absent, the design is wrong. | BUG-0005 | ux-designer, frontend-engineer |

## Closed

### BUG-0001 · Embedded content-credential manifests shipped inside brand assets

| | |
|---|---|
| Status | closed |
| Raised by | shehab |
| Raised on | 2026-09-14 |
| Run | brand foundation |
| Surface | logo |
| Component | `logo/svg/**` |
| Agent at fault | none, supplied files |
| Class | process |
| Severity | major |
| Evidence | original supplied SVGs |
| Fixed in | first commit, manifests stripped |
| Repeat of | none |

**What happened.** The three supplied lockups carried roughly 5KB of embedded base64
provenance metadata each, asserting tool authorship inside the brand assets themselves.

**Why it got through.** Nobody inspected the supplied files past the geometry.

**The rule this produces.** Any binary or markup asset entering the repository is read in
full before it is committed, including its metadata. Attribution is stripped wherever it
appears, not only from commit messages.

**Who must be briefed.** release-engineer, any agent committing an asset.

**How to detect it next time.** `grep -l 'c2pa\|xmpmeta\|Generator' logo/**/*.svg`

### BUG-0002 · Three skills cited the wrong BRAND.md section for voice rules

| | |
|---|---|
| Status | closed |
| Raised by | shehab |
| Raised on | 2026-09-21 |
| Run | 2026-09-21-verify-swarm |
| Surface | .claude/skills |
| Component | `actio-brand-guard`, `actio-bilingual-copy` |
| Agent at fault | authoring pass |
| Class | process |
| Severity | major |
| Evidence | `BRAND.md` section map |
| Fixed in | design system commit |
| Repeat of | none |

**What happened.** Three skills pointed at `BRAND.md` §2 for the voice rules. §2 is
Contrast. Voice is §5. The citations were written from the structure of the guidelines
PDF rather than from the machine-readable file.

**Why it got through.** The section numbers looked plausible and nobody opened the file.

**The rule this produces.** R-02. Section numbers are read, never remembered.

**Who must be briefed.** every agent that cites a spec.

**How to detect it next time.**
`grep -rn 'BRAND.md.*§' .claude | while read ...` then compare each against
`grep -n '^## ' BRAND.md`.

### BUG-0003 · Two conflicting definitions of run.json

| | |
|---|---|
| Status | closed |
| Raised by | shehab |
| Raised on | 2026-09-21 |
| Run | 2026-09-21-verify-swarm |
| Surface | .claude |
| Component | `orchestrator.md`, `actio-orchestration` |
| Agent at fault | authoring pass |
| Class | contract |
| Severity | blocker |
| Evidence | both files |
| Fixed in | design system commit |
| Repeat of | none |

**What happened.** `orchestrator.md` specified `run.json` with `plan[]` and `gates[]`. The
skill specified `stages[]` with a different key set. The utilisation check queries were
written against the shape that did not exist in the agent file, so they would have
returned nothing on a real run and reported a clean check on an unverified run.

**Why it got through.** The agent file and its skill were written separately and nobody
diffed the two schemas.

**The rule this produces.** R-03. One source per schema.

**Who must be briefed.** tech-architect, orchestrator, any agent defining a shared format.

**How to detect it next time.** For any JSON shape named in more than one file, extract
the top-level keys from each and diff them.

### BUG-0004 · Gate names disagreed across files

| | |
|---|---|
| Status | closed |
| Raised by | shehab |
| Raised on | 2026-09-21 |
| Run | 2026-09-21-verify-swarm |
| Surface | .claude, docs |
| Component | gate table |
| Agent at fault | authoring pass |
| Class | process |
| Severity | blocker |
| Evidence | gate name census |
| Fixed in | design system commit |
| Repeat of | BUG-0003 |

**What happened.** The review gate was `review` in some files and `review-1of2` and
`review-2of2` in others. Closure was `closure` in some and `run-closure` in others. The
utilisation check matches gate names literally, so it would have reported every gate as
unresolved.

**Why it got through.** Same root cause as BUG-0003: a shared vocabulary defined in more
than one place.

**The rule this produces.** `docs/WORKFLOW.md` is the single source for gate names, and it
carries the literal `name` column. Every other file references it.

**Who must be briefed.** orchestrator, every gate owner.

**How to detect it next time.**
`grep -rhoE '\b(design-authority|design|copy|review-[0-9]of[0-9]|regression-guard|engineering|quality|release|run-closure)\b' .claude docs | sort | uniq -c`
and confirm the set matches the gate table exactly.

### BUG-0005 · A 20px icon size invented outside the scale

| | |
|---|---|
| Status | closed |
| Raised by | shehab |
| Raised on | 2026-09-21 |
| Run | 2026-09-21-verify-swarm |
| Surface | .claude/skills |
| Component | `actio-design-system`, metric tile |
| Agent at fault | authoring pass |
| Class | brand |
| Severity | minor |
| Evidence | `BRAND.md` §1.5, §6 |
| Fixed in | design system commit |
| Repeat of | none |

**What happened.** The metric tile specified a 20px icon. 20 is not on the spacing scale
and `BRAND.md` puts icons on a 24px grid.

**Why it got through.** 20px is the size the eye wanted between 16 and 24, which is
exactly the drift the short scale exists to prevent.

**The rule this produces.** R-04.

**Who must be briefed.** ux-designer, frontend-engineer.

**How to detect it next time.**
`grep -noE '\b(14|18|20|30)px\b' <files>` and check every hit is inside a sentence
saying the value is banned.

### BUG-0006 · Design references read as a colour instruction

| | |
|---|---|
| Status | closed |
| Raised by | shehab |
| Raised on | 2026-09-21 |
| Run | 2026-09-21-verify-swarm |
| Surface | .claude/skills |
| Component | `actio-design-system` |
| Agent at fault | authoring pass |
| Class | design-system |
| Severity | major |
| Evidence | `docs/design-reference/` |
| Fixed in | this run |
| Repeat of | none |

**What happened.** The supplied references use a lime accent. The design system recorded
the accent as an open decision for the Product Lead rather than as settled, which left the
question live in a binding document.

**Why it got through.** The references were read as a full design instruction rather than
as a structural one.

**The rule this produces.** The references define look, feel and SaaS experience:
anatomy, density, hierarchy, interaction. They never define colour. Vega is the accent and
`BRAND.md` is the only source for it. A reference is never cited to justify a colour.

**Who must be briefed.** ux-designer, ux-auditor, frontend-engineer.

**How to detect it next time.** Any sentence in a design document that cites a reference
image as the reason for a colour value.

## Repeat offenders

The point of the register. Reviewed by `bug-historian` at the start of every run.

| Pattern | Occurrences | Standing rule |
|---|---|---|
| A shared vocabulary or schema defined in two files and allowed to drift | BUG-0003, BUG-0004 | R-03 |
| A spec value written from memory rather than read from the file | BUG-0002, BUG-0005 | R-02, R-04 |

Two occurrences of a pattern makes it a repeat. A third escalates to Shehab as a process
failure rather than a defect, because the register was written and not read.
